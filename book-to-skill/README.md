# Book to Skill

**把一本好书变成可复用的 Claude Code Skills。**

## 这是什么？

你有没有读过一本方法论书籍，觉得"这方法太棒了"，但合上书就忘了怎么用？

`book-to-skill` 帮你把书籍中的方法论转化成 Claude Code Skills——可交互、可复用的工具。

**例子：**
- 《原子习惯》→ habit-stack（习惯叠加规划器）、habit-scorecard（习惯记分卡）
- 《系统之美》→ system-trap-detector（系统陷阱识别器）
- 《纳瓦尔宝典》→ specific-knowledge-finder（专长发现器）

## 它能做什么？

1. **搜索书籍内容**——自动抓取书籍的核心概念、方法论
2. **提取 skill 方向**——分析书籍，识别 3-5 个可产品化的 skill
3. **用户选择**——让你选择想创建的 skills
4. **自动创建骨架**——生成完整的 skill 文件结构

## 安装

### 方法一：直接复制到你的 Claude Code skills 目录

```bash
git clone https://github.com/liigoQi/my-skills.git
cp -r my-skills/book-to-skill ~/.claude/skills/
```

### 方法二：手动安装

1. 下载 `skills/book-to-skill` 文件夹
2. 放到 `~/.claude/skills/book-to-skill/`

## 使用方法

在 Claude Code 中输入：

```
/book-to-skill 书名
```

例如：

```
/book-to-skill 原子习惯
/book-to-skill 系统之美
/book-to-skill 纳瓦尔宝典
```

## 一个完整的使用案例

```
用户: /book-to-skill 纳瓦尔宝典

Claude: 让我搜索《纳瓦尔宝典》的核心内容...

📚 《纳瓦尔宝典》分析完成，识别到以下skill方向：

1. **specific-knowledge-finder** - 专长发现器
   使用样例：
   - 输入：我工作五年了，感觉什么都会一点但都不精，跳槽时发现没有核心竞争力
   - 过程：回溯你的成长轨迹，找出"对你像玩耍、别人觉得是工作"的事
   - 输出：一份专长清单和可产品化方向

2. **leverage-audit** - 杠杆审计器
   使用样例：
   - 输入：我每天加班到10点，收入还是只够还房贷，感觉再努力也突破不了
   - 过程：分析你当前用的杠杆类型，找出"零杠杆"的环节
   - 输出：添加杠杆的具体行动路径

请选择您想创建的skills：
```

## 适合哪些书籍？

| 类型 | 例子 | 为什么适合 |
|-----|------|----------|
| 方法论书籍 | 《原子习惯》《深度工作》 | 有可复用的框架和方法 |
| 技术工具书 | 《代码整洁之道》《设计模式》 | 有可应用的规则和检查清单 |
| 框架指南 | 《OKR工作法》《敏捷开发实践》 | 有固定的工作流程 |
| 思维模型书 | 《思考快与慢》《原则》 | 有可迁移的分析框架 |

**不适合：**
- 纯叙事类书籍（小说、传记）
- 纯知识类书籍（百科、教材）
- 没有明确方法论的畅销书

## 核心理念

### 为什么是"使用样例"而不是"核心价值"？

传统的方法论分享是这样的：

> "这个框架的核心价值是帮助你更好地做决策..."

然后用户想："所以呢？我什么时候用？怎么用？"

我们换了一种方式——**使用样例**：

> "输入：我每天工作12小时，但产出和同事差不多，还累得不行"
> "输出：告诉你杠杆点在'信息流'层，而不是'参数'层"

**用户一看就知道：这说的就是我，我知道怎么用了。**

### 什么是"真实痛点"？

❌ 泛泛场景："想提升产品竞争力"（太抽象）
✅ 真实痛点："我每天工作12小时，产出却和同事差不多"（有共鸣）

好的使用样例让用户觉得"这说的就是我"，而不是"好像有点道理"。
