# Book to Skill

## Overview

这个skill帮助用户将一本好书转化为实用的Claude Code skills。它会：
1. 搜索书籍内容（全文/摘要/核心章节）
2. 分析书籍，提取3-5个最有价值的skill方向
3. 让用户多选想要创建的skills
4. 自动初始化选中的skill骨架

## When to Use

**触发场景：**
- 用户说"帮我从这本书创建skill"、"把这本书变成skill"
- 用户给了一个书名，希望将其方法论转化为可复用的工具
- 用户说"我想用XXX书的方法来..."，希望系统化地应用书中知识

**适合的书籍类型：**
- 方法论书籍（如《原子习惯》《深度工作》）
- 技术工具书（如《代码整洁之道》《设计模式》）
- 框架指南（如《OKR工作法》《敏捷开发实践》）
- 思维模型书（如《思考快与慢》《原则》）

## Workflow

### Step 1: 接收书名

用户输入书名后，确认书籍信息：

```
请确认书籍信息：
- 书名：《XXX》
- 作者：XXX（如果能确定）
- 语言偏好：中文/英文/均可
```

### Step 2: 搜索书籍内容

使用Web Search（bailian_web_search）工具，按以下优先级获取内容：

**搜索策略（按优先级）：**

1. **官方全文**（开放版权、作者公开版本）
   - `{书名} 作者 官方 全文`
   - `{书名} pdf author official`

2. **其他渠道公开资源**（txt、epub、pdf等）
   1. `{书名} 作者 txt epub pdf 资源`

3. **出版社/作者官网摘要**
   - `{书名} 目录 章节摘要`
   - `{书名} table of contents summary`

4. **读书平台深度内容**
   - `{书名} 豆瓣 读书笔记 核心概念`
   - `{书名} goodreads summary key concepts`

5. **可靠书评/解读**
   - `{书名} 书评 深度解读`
   - `{书名} book review analysis`

### Step 3: 分析提取Skill方向

根据书籍内容，从以下维度提取skill方向：

**分析框架：**

| 维度 | 分析问题 | Skill类型示例 |
|------|----------|---------------|
| 核心方法论 | 书中有什么可复用的方法/框架？ | 计划生成器、方案设计器 |
| 诊断工具 | 书中如何诊断问题？ | 质量检测、健康度评估 |
| 检查清单 | 书中有什么checklist？ | 审查清单、启动检查 |
| 模板生成 | 书中有什么固定格式？ | 文档模板、报告格式 |
| 分析框架 | 书中如何分析问题？ | SWOT分析、根因分析 |
| 对话指南 | 书中有什么对话脚本？ | 沟通模板、反馈话术 |
| 评分系统 | 书中如何量化评估？ | 成熟度评估、能力矩阵 |
| 决策工具 | 书中如何辅助决策？ | 决策矩阵、选择框架 |

**输出格式：**

每个skill必须包含**使用样例**，让没读过书的用户也能直观理解其价值：

```
📚 《书名》分析完成，识别到以下skill方向：

1. **{skill-name}** - {一句话描述}
   使用样例：
   - 输入：{用户具体会输入什么问题/场景}
   - 过程：{skill会做什么分析/处理}
   - 输出：{用户最终得到什么结果}

2. **{skill-name}** - {一句话描述}
   使用样例：
   - 输入：...
   - 过程：...
   - 输出：...

请选择您想创建的skills（可多选）
```

**样例编写原则：**

**输入必须是"真实痛点"——用户一看就觉得"这说的就是我"：**
- ❌ 泛泛场景："想提升产品竞争力，但不知道从哪里下手"（太抽象）
- ✅ 真实痛点："我每天工作12小时，但产出和同事差不多，还累得不行"（具体、有共鸣）
- ❌ 抽象问题："如何更好地管理时间"（像教科书标题）
- ✅ 真实困扰："开会占用了我大半个下午，实际干活时间只有2小时"（场景感强）

**判断标准：**
- 用户看到输入时会想"对，我就是这样的"而非"嗯，好像有点道理"
- 输入要有具体的情境、时间、人物、矛盾（不能只是一个泛泛的需求陈述）
- 过程要具体说明skill的分析步骤（让用户理解"怎么做"）
- 输出要展示用户能拿到的具体结果（不能只是"帮助你..."这种模糊描述）
- 整个样例要形成完整的"痛点→诊断→方案"闭环

### Step 4: 用户选择

使用AskUserQuestion工具，让用户多选想要的skills：

- 每个选项包含：skill名称、描述、核心价值
- 提供"全选"选项
- 允许用户自定义修改

### Step 5: 创建Skills

对每个选中的skill执行：

**5.1 初始化skill骨架**
```bash
python3 {init_skill.py路径} {skill-name} --path {目标路径}
```

**5.2 填充SKILL.md内容**
- 根据书籍内容编写description
- 设计workflow结构
- 添加具体步骤和示例

**5.3 添加参考资源**
- 在references/中添加书籍核心概念的详细说明
- 添加模板、检查清单等资源文件

**5.4 报告创建结果**
```
✅ 已创建 {n} 个skills：
- skill-name-1: /path/to/skill-name-1
- skill-name-2: /path/to/skill-name-2

每个skill包含：
- SKILL.md: skill主文件
- scripts/: 可执行脚本
- references/: 参考文档
- assets/: 资源文件
```

## Example Session

```
用户: 帮我从《原子习惯》这本书创建skill

Claude: 让我搜索《原子习惯》的核心内容...

[使用WebSearch搜索书籍内容...]

📚 《原子习惯》分析完成，识别到以下skill方向：

1. **habit-stack** - 习惯叠加规划器
   使用样例：
   - 输入：我每天早上刷牙后就出门了，根本想不起来要读书，怎么都养不成阅读习惯
   - 过程：识别你的固定习惯"刷牙"，设计叠加"刷牙后→读2页书"，绑定到现有流程上
   - 输出：一个具体的习惯叠加表，如"刷牙后→读2页书→记录一句感想"

2. **habit-scorecard** - 习惯记分卡
   使用样例：
   - 输入：我每天刷3小时短视频、喝两杯奶茶、熬夜到1点，感觉身体被掏空了但停不下来
   - 过程：逐个评估每个习惯的正负影响，计算"习惯净得分"
   - 输出：一份带+/-分的习惯清单，告诉你"奶茶是-2分（提神但影响睡眠），短视频是-3分（纯消耗）"

3. **implementation-intention** - 执行意图生成器
   使用样例：
   - 输入：我想健身，买了年卡去了两次就不去了，总是"今天太忙了"找借口
   - 过程：把"我要健身"拆解成"每周一三五18:30，在公司楼下健身房，换好衣服就开始，不做完不走"
   - 输出：4个具体的执行意图，每个都有明确的时间、地点、触发条件

4. **environment-design** - 环境设计助手
   使用样例：
   - 输入：我想戒掉夜宵，但一到晚上10点就忍不住打开冰箱找吃的
   - 过程：分析你的环境触发点——冰箱里有零食、零食放在视线范围内，设计"让坏习惯变难"的改造
   - 输出：具体的环境改造清单，如"冰箱里只放蔬菜"、"零食锁进柜子顶层需要搬凳子才能拿到"

请选择您想创建的skills：
```

用户选择后 → 自动创建对应skill文件 → 返回创建结果

## Important Notes

- **内容验证**：创建skill前展示分析结果让用户确认
- **skill命名**：使用hyphen-case（如habit-stack），简洁明了，最多40字符
- **持续优化**：创建后可根据用户反馈迭代skill内容
- **质量保证**：确保提取的skill方向确实源自书籍核心价值，而非泛泛而谈
